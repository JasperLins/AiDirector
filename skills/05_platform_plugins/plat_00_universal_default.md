# 公用默认标准提示词插件（PLAT-00）· 工业级完整版

## 一、核心职责与工业级法则（6 条硬核铁律）

1. **安全交集铁律**：公用版只使用全平台安全交集语法——纯中文自然语言、`@资产名` 引用、`[00-02s]` 秒级节点、空间分区句式、口型排他锁；**严禁**混入任何平台专属件（MiniMax 方括号运镜、即梦素材位计数、可灵四段式、ComfyUI 节点参数）——语法污染会让"通用版"在半数平台失效。
2. **推荐必附铁律**：输出公用版的同时必须给出"首推平台+次推平台+理由"，理由必须引用优劣矩阵的具体维度（"S 级大幅动作→可灵：首尾帧锚定+物理规律模拟强项"），禁止"都行/看喜好"。
3. **迁移提示铁律**：每条公用 Prompt 附"迁移差异清单"——转即梦补素材位清单+一致性行；转可灵补首尾帧声明+四段式重排；转 MiniMax 补方括号运镜+声音设计栏；转 ComfyUI 补中英双轨+节点参数+负向包；转豆包补三层空间分句+4K 词缀。
4. **互斥加载铁律**：本插件与 plat_01~05 互斥——用户一旦指定平台立即卸载本插件转对应插件；跨平台对比场景必须分次产出独立代码块并逐块标注平台名。
5. **公式对齐铁律**：公用公式即 `KB_08` 编译器的平台中立投影——生图八层全量、视频 20/80 差分；本插件不得增删公式层，只做"语法中立化"。
6. **风险前置铁律**：输出时必须预告该镜头类型在推荐平台的已知崩坏点（引用黑名单编号），让用户抽卡前就知道要盯什么。

## 二、标准执行 SOP（Step-by-Step）

**Step 1 · 读入镜头特征**：任务类型、景别、动作幅度、资产数、台词模式、题材——五个特征向量。

**Step 2 · 查矩阵定推荐**：按 4.1 优劣矩阵逐维度比对，得出首推+次推平台与理由；同时读 `memory/global/权威工作流与影视知识库.md` 三节选型路由表交叉验证。

**Step 3 · 编译公用版**：按 4.2 公式（生图八层 / 视频 20/80 差分）编译全平台安全交集语法的中文 Prompt，代码块封装。

**Step 4 · 生成迁移提示**：按铁律 3 逐平台列差异清单。

**Step 5 · 风险前置**：按镜头类型引用黑名单编号输出 1~2 条已知崩坏点与盯片要点。

**Step 6 · 送检**：R7 评分 ≥9.0 后交付；产出文档标注"默认公用提示词（附最佳模型推荐）"。

### 4.2 公用标准中文提示词完整公式

**生图（八层全量）**：
```text
[主体层 @资产+骨相5~8词] + [服饰层 四件套] + [动作层 单一姿态+手部状态] + [空间层 分区句式(多人)] + [环境层 场景三层+时间天气] + [光学层 光型+色温+过曝防护] + [镜头层 景别+机位+构图] + [画风层 @画风锁+线别缀] + [规格 画幅+分辨率]
```
**生视频（20/80 差分）**：
```text
[锚点20% @资产+≤2骨相词] + [动态80% 运镜1种+幅度｜主动作1个｜微动作1个｜材质动态｜光影变化(可选)] + [时长层 秒级节点≤3] + [口型层 模式A台词+排他锁 / 模式B闭嘴基底] + [画风层 @画风锁+缀] + [规格 画幅+秒数]
```

## 五、常见错误示范 vs 满分工业级示范

### 对比组 1：公用版语法污染

❌ **Bad Case**：
> （用户未指定平台的）公用提示词：`[推近]镜头…素材位1上传@李梅…负向词：多余手指…`混合了 MiniMax 方括号、即梦素材位、ComfyUI 负向输入三种专属语法。

**扣分点**：违反安全交集铁律——方括号在豆包/可灵被当普通文本、素材位计数在无素材位平台误导用户、负向词在不支持负向输入的端直接画进画面。

✅ **Good Case**：
> 公用版纯安全交集（见 4.3 示例②），随后附迁移提示："转 MiniMax：句首运镜改 `[推近]缓慢`+段尾补声音设计栏；转即梦：前置素材位清单；转 ComfyUI：补英文双轨与负向包输入端。"

### 对比组 2：无理由推荐

❌ **Bad Case**：
> 这个镜头用哪个平台都差不多，你自己挑一个顺手的就行，提示词我已经写好了。

**扣分点**：推荐必附铁律违例——无矩阵维度引用、无崩坏风险预告；用户在错误平台抽卡浪费的每一次都是框架的责任。

✅ **Good Case**：
> 首推即梦 Seedance 2.5（模式A对白直出+素材位双锁，矩阵"多主体交互★"）；次推 MiniMax H3（"人物特写★★"，微表情细腻）；风险预告：双人同框盯崩坏06 串脸与崩坏05 乱张嘴——排他锁已写入，抽卡取"双脸同真"那张。

## 六、边界情况处理（Edge Cases）

1. **跨平台对比需求**：分次激活各平台插件产出独立代码块，逐块标注平台名；禁止一条 Prompt 标"多平台通用"之外再标某平台专属件。
2. **平台能力更新（模型迭代）**：以 `memory/global/权威工作流与影视知识库.md` 为准——复盘引擎 EVO-01 检测到平台语法变更时先更新知识库再更新本矩阵，本插件矩阵注明"最后核实日期"。
3. **用户受限（无本地显卡/无某平台配额）**：推荐链自动裁剪排除项（ComfyUI 需显存、可灵需配额），沿"即梦→MiniMax→豆包"降级。
4. **B 级降本镜头**：推荐固定为"不生成视频"（静态图+Lip-Sync+剪映关键帧）——本插件输出静态图 Prompt 与 R8 动效指令单，不走视频推荐链。
5. **公用版被用户直接拿去不支持中文的平台**：迁移提示中显式警告"目标平台中文支持弱，请转 ComfyUI 英文双轨版"，并附英文对照串（KB_06）。
